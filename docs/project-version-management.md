# 项目配置版本管理

应用会从已打开 `.jcpro` 的所在目录向上查找最近的 Git 工作树。仓库存在时，
“项目管理”页面会显示当前分支、提交、受管文件状态和项目版本历史。

## 置顶版本摘要

工作区顶部的 Git 分支按钮在所有功能页面保持可见。点击后会显示紧凑摘要：

- 受管配置的新增、删除行数；
- 本地仓库名称和打开仓库目录的入口；
- 当前分支与 HEAD 短哈希；
- 项目版本提交状态；
- 本地版本历史数量和详细历史入口。

摘要中的提交动作沿用项目页的安全检查。编辑器仍有未保存内容、Git 暂存区已有
其他内容或配置没有磁盘变更时，提交入口会停用。

## 更改审阅

从版本摘要的“变更”或“审阅更改”进入审阅工作区。审阅范围与项目版本提交范围
一致，只包含当前 `.jcpro` 和关联 sidecar，不会把仓库中的其他源码混入提交。

审阅工作区提供：

- 受管文件导航和新增、修改、删除状态；
- 当前分支、上游分支和汇总增删行数；
- unified diff 区块、旧/新双行号以及新增、删除行着色；
- 统一视图与左右并排视图切换，并记住最近选择；
- 单文件或全部文件折叠、文件定位和刷新；
- 版本说明编辑及项目版本提交。

未跟踪的 sidecar 会按完整新增文件显示。提交完成后审阅内容会立即刷新为空状态。

## 受管文件

每个项目只管理明确关联的配置文件：

- 当前 `.jcpro`；
- 已挂载的重构配置 JSON；
- 与项目同名且已存在、已被 Git 跟踪或有历史记录的
  `<项目名>.refactor-config.json`。

应用不会执行 `git add .` 或 `git add -A`，UI 图片、源码、导出结果和仓库中的
其他文件不会自动加入项目版本。

## 保存版本

先保存编辑器中的项目修改，再填写版本说明并点击“保存版本”。后端会：

1. 确认项目文件仍位于检测到的 Git 工作树中；
2. 拒绝存在未解决冲突或既有暂存内容的仓库；
3. 只暂存受管配置路径；
4. 确认暂存区没有混入其他文件；
5. 创建 Git 提交并刷新版本历史。

已有暂存内容时需要先在外部 Git 工具中提交或取消暂存。该限制用于避免项目
版本提交夹带用户正在准备的其他改动。

## 查看和恢复

“查看”会直接从 Git 对象中读取指定提交的 `.jcpro` 和 sidecar JSON，不会修改
工作树。选择“恢复为工作副本”后，历史内容只会载入编辑器并标记为未保存修改；
确认保存后可再创建一个新版本。

恢复操作不会执行 `git reset`、`git checkout`，也不会回退分支 HEAD。

## 未使用 Git 的项目

找不到 Git 工作树时，项目仍可正常编辑和保存。应用不会自动初始化仓库；如需
版本管理，请先在项目目录或父目录中执行 `git init` 并建立初始提交。
